# ruvm v0.7：能用的系統

v0.7 讓兩種架構的 Linux 都能從真正的磁碟映像開機、寫入資料、重開機後資料還在。

```
$ tools/linux/fetch-debian.sh          # Debian 核心 (一次)
$ tools/linux/mkroot.sh                # 小型 initramfs + ext4 根檔案系統 (不需 Docker/編譯器)
$ ruvm -M aarch64 -m 512 -kernel tests/guest/out/linux/debian/arm64/linux \
       -initrd tests/guest/out/linux/root/arm64/initramfs.cpio.gz \
       -drive file=tests/guest/out/linux/root/arm64/root.ext4 -rng \
       -append "console=ttyAMA0 rdinit=/init" -serial stdio
```

| 項目 | 說明 |
|---|---|
| virtio 重構 | `src/virtio/`：通用 virtio-mmio v2 傳輸層（多個 virtqueue、多個裝置槽位）+ 可插拔後端 `Backend`（`blk`、`rng`、`net`）。後端回傳 `Used(n)` 或 `NotReady`（接收緩衝區先放著等封包），傳輸層在每次寫暫存器與每個輪詢週期處理佇列，所以後端能非同步完成請求。 |
| 多槽位 | 槽位與 QEMU `virt` 相同：RISC-V `0x1000_1000 + n·0x1000`（PLIC 1+n），ARM `0x0a00_0000 + n·0x200`（SPI 16+n）。device tree 依實際裝置產生。 |
| virtio-rng | xorshift64*，預設用主機時間播種，`-rng-seed N` 可重現。 |
| RTC | RISC-V：Goldfish RTC（`0x10_1000`）；ARM：PL031（`0x0901_0000`）。兩者都是 Linux 內建驅動，開機時自動設定系統時間。預設跟主機時鐘，`-rtc <秒>` 固定起始時間。 |
| 真正的重開機 | `Stop::Reset`：SBI SRST（reset 類型）、PSCI `SYSTEM_RESET`、test finisher `0x7777` 都會重開機：RAM 清空、裝置重置、重新載入同樣的映像，磁碟內容保留（`Disk` 是共用的 `Arc`）。`-no-reboot` 則直接結束。 |
| 多個 `-drive` | 依序成為 virtio-blk 裝置，再來是 `-rng`。 |

## 根檔案系統怎麼做

`tools/linux/mkroot.sh` 只用 Debian 套件，不需要編譯：

1. `busybox-static`（靜態連結）。
2. 與核心同版本的 udeb：`ext4-modules`（`ext4`、`jbd2`）、`scsi-modules`（`virtio_blk`）；
   `crc16`、`crc32c`、`mbcache`、`virtio_mmio`、`virtio-rng` 來自 netboot initrd。
3. 模組在主機端解壓縮（busybox 的 `insmod` 讀不了 `.xz`），並**移除附加的簽章**：
   驗證簽章要對整個模組算 SHA-256，在模擬器上要花很多指令，而且核心不強制簽章。
4. `initramfs`：依序 `insmod`，等 `/dev/vda`，掛載 ext4，`switch_root`。
5. `mke2fs -d` 直接從目錄產生 64 MiB 的 ext4 映像。

用小 initramfs 取代 60 MB 的安裝程式 initrd 後，ARM 開機從約 2 分鐘降到約 35 秒。

## 測試

`cargo test --release -- --ignored` 會跑 `linux_ext4_root_reboot_*`：第一次開機在磁碟上寫計數器 1 並 `reboot -f`，
第二次開機必須讀到計數器並確認 RTC 年份（固定起始時間 2030）與 `/dev/hwrng` 可讀，最後 `poweroff`。
之後用 `e2fsck` 檢查映像沒有損壞（RTC 時間在主機看起來「在未來」只是時間戳記警告）。
