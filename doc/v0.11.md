# ruvm v0.11：指令集補完

補上前幾版刻意略過的指令與特權功能，全部與 QEMU 逐位元（逐 trap）比對。核心看得到這些功能並實際使用。

## AArch64

| 項目 | 說明 |
|---|---|
| FP 估計指令 | `FRECPE` / `FRSQRTE`（單、雙精度，向量與純量）、`FRECPX`、`URECPE` / `URSQRTE`；依架構虛擬碼的 9 位元查表演算法，含 DZ/OF/NV 旗標與捨入模式對溢位結果的影響 |
| CRC32 | `CRC32{B,H,W,X}`、`CRC32C{B,H,W,X}` |
| AES | `AESE` / `AESD` / `AESMC` / `AESIMC`（S-box 由 GF(2⁸) 反元素 + 仿射轉換在啟動時算出，不內嵌表格） |
| SHA | `SHA1C/P/M/H/SU0/SU1`、`SHA256H/H2/SU0/SU1`（PMULL 64→128 在 v0.6 已有） |
| 原子 | `CASP` / `CASPA` / `CASPL` / `CASPAL`（LSE 其餘部分 v0.2 已有） |
| 宣告 | `ID_AA64ISAR0_EL1` 宣告 AES+PMULL、SHA1、SHA2、CRC32、LSE：Linux 顯示 `fp asimd evtstrm aes pmull sha1 sha2 crc32 atomics`，並把自己的原子操作換成 LSE 版本（指令更少，開機更快） |

差分測試 `a64_neon` 由 2074 組增為 2136 組，全部與 `qemu-system-aarch64 -cpu max` 相同。
實作過程中差分測試抓到：AESD 的 InvShiftRows 方向寫反（用了 scatter 而不是 gather）、SHA256SU1 串接順序（`Z<31:0> : Y<127:32>` 的高低位）。

## RISC-V

| 項目 | 說明 |
|---|---|
| Zba / Zbb / Zbs / Zbc | `sh1add`…、`add.uw`、`slli.uw`、`clz/ctz/cpop(w)`、`min/max`、`rol/ror(i)(w)`、`rev8`、`orc.b`、`sext.b/h`、`zext.h`、`andn/orn/xnor`、`bclr/bext/binv/bset(i)`、`clmul/clmulh/clmulr`；`misa.B` |
| Zicond | `czero.eqz` / `czero.nez` |
| Zicbom / Zicboz | `cbo.inval/clean/flush/zero`（64 位元組區塊）；S/U 模式受 `menvcfg` / `senvcfg` 的 `CBIE/CBCFE/CBZE` 控制；被擋時是 illegal instruction（`mtval = 0`，與 QEMU 一致） |
| Svinval | `sinval.vma`、`sfence.w.inval`、`sfence.inval.ir` |
| Sv48 | 四層頁表；`satp` 模式 9。核心會自動選用最大的支援模式（`/proc/cpuinfo` 顯示 `mmu: sv48`） |
| **PMP（強制執行）** | 16 個區域；OFF / TOR / NAPOT（NA4 見下）；lock 位元（鎖定的區域也約束 M-mode、且寫入被忽略）；S/U 存取沒有任何符合的區域就失敗（與規格和 QEMU 一致）。內建 SBI 開機時像 OpenSBI 一樣先設一個涵蓋全部記憶體的 RWX 區域。 |

DT 會宣告這些擴充（`riscv,isa-extensions`、`riscv,cbom-block-size`、`riscv,cboz-block-size`、`mmu-type = riscv,sv48`），
核心也確實使用它們：`isa : rv64imafdc_zicbom_zicboz_zicntr_zicond_zicsr_zifencei_zihintpause_zca_zcd_zba_zbb_zbc_zbs_sstc_svinval`。

### 與 QEMU 的細節

* **NA4**：QEMU 的 PMP 粒度大於 4 位元組，NA4 模式不可用；ruvm 的實作支援 NA4，但差分測試不涵蓋（測試改用 TOR）。
* **PMP 檢查大小**：只檢查存取的第一個位元組，沒有檢查跨越區域邊界的存取，也沒有檢查硬體頁表走訪。
* **cbo 被擋的 `mtval`**：QEMU 為 0（規格允許兩者），ruvm 配合。

## 驗證

* `rv_bitmanip`（`gen_rv_bitmanip.py` 產生）：66 組指令 × 22×22 個邊界運算元。
* `rv_ext`：M-mode 設定 PMP 後在 S-mode 做存取，逐一比對每次 trap 的 `cause` / `tval`，涵蓋各種區域類型、鎖定區域、
  cbo 開關、Svinval、Sv48（含非正規位址、未映射、唯讀頁）。
* 所有 8 個 Linux 測試（開機、ext4 重開機、網路、SMP；兩種架構）在新功能開啟下仍通過。

## 仍未實作

* **RISC-V V（向量）擴充**：指令與暫存器數量很大，暫不實作；DT 不宣告，所以核心與 glibc 不會使用。
* Sv57、H（虛擬化）、Zfh、Smepmp、AIA/IMSIC。
* ARM：EL2/EL3、SVE、PAuth/BTI/MTE、SHA512/SHA3/SM3/SM4、BF16 / dot-product。
