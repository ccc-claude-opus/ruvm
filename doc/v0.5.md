# ruvm v0.5：RISC-V Linux

v0.5 讓 **Debian 13 的原廠 riscv64 核心**（Linux 6.12，`debian-installer` netboot 映像）
在 ruvm 上開機到 busybox shell、執行指令並正常關機。

```
$ tools/linux/fetch-debian.sh riscv64
$ ruvm -M riscv64 -m 512 -kernel tests/guest/out/linux/debian/riscv64/linux \
       -initrd tests/guest/out/linux/debian/riscv64/initrd.gz \
       -append "console=ttyS0 rdinit=/bin/sh" -serial stdio
...
[  240.609150] Run /bin/sh as init process

~ # uname -a
```

## 為什麼用 Debian 的核心

原本的計畫是用 Docker 自己編一個最小核心與 busybox（`tools/linux/build.sh`，仍保留）。
但這台機器的磁碟只剩幾 GB，解開 Linux 原始碼時 Docker VM 就因為主機磁碟滿了而出現 I/O 錯誤。
改用 Debian 官方的 netboot 核心反而是更嚴格的測試：它是一般發行版的設定（SMP、ACPI、
PMU、各種驅動程式都開著），而不是為模擬器量身打造的最小核心。

## 這一版修正 / 新增的東西

| 項目 | 原因 |
|---|---|
| SBI PMU 擴充（最小版） | Linux 的 `riscv-pmu-sbi` 驅動程式在 CPU 啟動時才設定 `scounteren`；沒有它，使用者模式的 `rdtime`（glibc 的 `clock_gettime`）會變成非法指令，busybox 一啟動就收到 SIGILL。只提供 cycle (0) 與 instret (2) 兩個固定計數器，不支援事件。 |
| `-send-after <pattern> <text>` | 像 `expect`：等 console 印出某字串後才「打字」。開機途中先打的字會被 8250 驅動程式在開 port 時清掉（真實硬體也一樣），所以腳本化測試需要它。 |

## 開機所需的指令數

約 45 億個指令到 shell（模擬時間約 240 秒，因為每個指令算 1 tick = 0.1 µs），
在 Apple Silicon 上實際約 70 秒。效能改善會在之後的版本處理。
